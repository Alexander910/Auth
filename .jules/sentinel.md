## 2025-03-04 - Mass Assignment Vulnerability in User Registration Flow
**Vulnerability:** The register API endpoint allowed clients to pass arbitrary parameters in `req.body` directly, including the `role` field. An attacker could register an account and assign themselves the "admin" role directly without authorization, leading to privilege escalation.
**Learning:** The application was destructuring and passing `role` directly from `req.body` into `AuthService.register`, which in turn supplied it to `UserService.createUser` and Mongoose. When input validation and parameter sanitization are missing at the boundary layers (Controllers/Services), clients can modify model fields they shouldn't have access to.
**Prevention:** Always explicitly define and destructure permitted fields from incoming request payloads (using DTOs or explicit variable assignment). Never pass complete client-supplied JSON objects directly to services or database creators without sanitization, and enforce default restricted values (like `role: "user"`) at the service level.
